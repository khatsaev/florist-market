# Флорист Маркет

**[Открыть демоверсию с телефона или компьютера](https://khatsaev.github.io/florist-market/)** · [Исходники на GitHub](https://github.com/khatsaev/florist-market)

На GitHub Pages все разделы и операции работают с личной копией тестовой базы **в браузере**. Изменения сохраняются при перезагрузке, но не синхронизируются между устройствами; очистка данных сайта их удалит. Демо не передаёт операции на общий сервер. Локальная версия ниже использует отдельный Express-сервер и SQLite-файл.

Рабочий локальный MVP управления магазином флористической упаковки: склад, производство шляпных коробок и колб, управленческие финансы и учебная касса. Русский адаптивный интерфейс вдохновлён вашим приложением ATECH: тёмная сине-зелёная тема, мятные акценты и IBM Plex Sans.

**Это демонстрационная система. Она сохраняет операции, но не принимает реальные платежи, не формирует фискальные чеки и не ведёт регламентированный бухгалтерский учёт.**

## Быстрый запуск

Требуется **Node.js 22.13 или новее**, npm и доступ к интернету для первой установки зависимостей. Проверено в среде Node.js 25.8.0. Для последующего запуска внешние сервисы не нужны: шрифты и интерфейс поставляются локально.

1. Откройте терминал в папке `florist-market`.
2. Установите зависимости по зафиксированным версиям:

   ```sh
   npm ci
   ```

3. Проверьте и соберите интерфейс:

   ```sh
   npm run build
   ```

4. Запустите приложение:

   ```sh
   npm start
   ```

5. Откройте **http://127.0.0.1:4173**. Для остановки нажмите Ctrl+C в терминале.

На macOS можно запустить файл **«Запустить.command»** из папки проекта. Он установит недостающие зависимости, пересоберёт интерфейс и запустит сервер. Если система блокирует файл из скачанного архива, используйте команды выше; отключать системные средства защиты не нужно.

Для разработки: `npm run dev`. Интерфейс обновляется при изменениях; после изменения серверных файлов перезапустите сервер. Другой порт: `PORT=4174 npm start` (macOS/Linux). По умолчанию сервер доступен **только на этом компьютере**.

## Интернет-демоверсия

```sh
npm ci
npm run build:demo
npm run preview:demo -- --port 4180
```

Откройте `http://127.0.0.1:4180/florist-market/`. Нужен современный браузер с WebAssembly и IndexedDB. `build:demo` собирает вариант для GitHub Pages; `build` — интерфейс локального сервера. Обе команды обновляют `dist`, поэтому перед `npm start` выполните обычный `npm run build`.

Развёртывание демо описано в [docs/PUBLISHING.md](docs/PUBLISHING.md). Доменная логика и SQL-схема общие для обоих режимов, финансовые правила не дублируются.

## Попробуйте сквозные сценарии

### Сырьё → коробка → продажа → возврат

1. «Производство» → «Новый заказ» → выберите спецификацию и количество.
2. Откройте заказ и проверьте потребность в сырье.
3. «Запустить производство»: материалы спишутся, их стоимость перейдёт в незавершённое производство.
4. «Выпустить … на склад»: готовый товар поступит на склад, его средняя себестоимость пересчитается.
5. «Касса»: если смена закрыта или просрочена, откройте новую; добавьте товар, скидку и способ оплаты.
6. «Оформить продажу» → подтвердите учебную операцию. Остаток уменьшится; продажа появится в финансах и отчётах.
7. «Продажи и возвраты» → кнопка возврата → количество и причина. Товар вернётся на склад, деньги и себестоимость сторнируются по исходной продаже.

### Приёмка и долг

1. «Товары и склад» → «Приёмка / списание»: укажите товар, количество, закупочную цену и основание.
2. Отметьте оплату только если деньги уже выплачены. Это создаст денежное движение по закупке, без немедленного расхода в прибыли.
3. Для неоплаченной поставки **отдельно** внесите долг в «Финансы» → «Задолженности». Автоматического сопоставления долга с поставкой в MVP нет.
4. Погашайте долг частями или целиком. Погашение меняет движение денег; повторно доход/расход не признаётся.

## Данные, копии и восстановление

Рабочая база: `data/florist.sqlite`; SQLite также может создавать файлы `-wal` и `-shm`. Страница не хранит бухгалтерские данные в localStorage. В этой версии один склад и один локальный управляющий без логина.

- **Резервная копия:** `npm run backup` создаёт согласованную копию в `backups/`, включая актуальные данные при работающем приложении.
- **Восстановление:** остановите сервер; сохраните существующую папку `data` под другим именем; создайте новую `data` и скопируйте резервную копию как `data/florist.sqlite`; запустите приложение. Не смешивайте новую базу со старыми `-wal` / `-shm`.
- **Чистое демо:** остановите сервер и переименуйте всю папку `data`, затем запустите приложение. Старая база останется в резервной папке, новая заполнится тестовыми данными.
- **Отдельная база:** `DB_PATH=/полный/путь/demo.sqlite npm start`. Не подключайте рабочую базу другой системы.
- CSV — выгрузка для анализа, **не полноценная резервная копия**. Массовое добавление карточек доступно через «Товары и склад» → «Импорт товаров» из JSON; [формат и подготовленный каталог из 57 товаров](docs/PRODUCT_IMPORT.md). Импорта CSV и восстановления базы из интерфейса пока нет.

## Правила и ограничения учёта

- Деньги хранятся в целых копейках. Количества — в тысячных единицы: `1000` означает 1 шт / м / кг. Штучные товары принимаются, продаются и возвращаются только целыми единицами.
- У каждой комбинации размера/цвета свой SKU. Один основной склад; перемещения между складами, серии, резервы и адресное хранение не реализованы.
- Себестоимость — средневзвешенная с округлением до копейки за единицу. Возможны копеечные округления стоимости запасов. Исторические продажи хранят собственные цены, скидки и себестоимость.
- Скидка округляется до копейки **на единицу товара**. Возврат использует сохранённую цену единицы, поэтому полный возврат точно равен исходной продаже.
- План не резервирует сырьё; запуск списывает его в НЗП одной операцией. Отмена разрешена только до запуска. Частичный выпуск, возврат сырья из НЗП, брак партии и исправление завершённого выпуска не реализованы.
- Заказ сохраняет снимок спецификации. Материальные затраты фиксируются при запуске; нормативные труд и накладные добавляются при выпуске. Это оценка производственной себестоимости, не полноценный учёт начисленной зарплаты и общепроизводственных расходов.
- Чтобы не задвоить расходы, не вносите уже капитализированные в выпуске труд/накладные как обычный расход периода. Полноценное отражение оплаты этих затрат, распределение отклонений и начислений требует расширения модели; в MVP ручные расходы предназначены для прочих расходов периода.
- Продажа признаёт выручку и себестоимость; возврат уменьшает их на дату возврата. Неденежное списание запасов уменьшает управленческий результат, но не денежный поток.
- Долги — отдельный начальный/ручной реестр. Создание долга само по себе не признаёт выручку, расход или движение товара. Продаж в кредит и частичных оплат заказа в POS нет.
- Ручные финансовые операции относятся к расчётному счёту. Кассовая смена считает только размен, наличные продажи и наличные возвраты. Инкассации, внесения и выплаты из кассового ящика не реализованы.
- Продажи, возвраты и движения сохраняются, а не удаляются из интерфейса. Редактирование проведённых документов и произвольное изменение дат не предусмотрены.
- НДС не выделяется, налоги не рассчитываются. Прибыль — управленческая оценка до налогов, все суммы показаны целиком.

## Проверки

```sh
npm run build
npm test
```

`npm test` включает доменные тесты и HTTP-интеграцию на отдельном локальном порту **14873** с временной базой; рабочие данные не изменяются. Интеграционный тест требует свободного порта и собранного `dist/`, поэтому сначала выполните `npm run build`.

Проверены: транзакционный откат, дефицит, повторное проведение, версии спецификаций, средняя себестоимость, скидки, частичные возвраты, наличные, граница 24 часа, долги, отчёты, перезапуск базы, Host/Origin/CSRF и HTTP-ошибки. Результаты и ручные проверки — в [docs/QA.md](docs/QA.md).

## Архитектура и дальнейшая разработка

- React + TypeScript + Vite; разделы подгружаются отдельно, шрифты локальные.
- Node.js + Express; сервер валидирует каждую операцию через Zod.
- Встроенный SQLite, WAL, транзакции и уникальные индексы.
- Документация: [архитектура](docs/ARCHITECTURE.md), [дизайн](docs/DESIGN.md), [правовые границы и интеграции](docs/COMPLIANCE.md).

Публичного развёртывания не выполнялось. Для работы сотрудников через интернет нужны авторизация и роли, HTTPS, управление доступом, защита персональных данных, мониторинг, резервные копии, многопользовательские проверки и подключение ККТ/эквайринга/бухгалтерии. Демонстрационный интерфейс нельзя просто выставить в интернет без этих доработок.
