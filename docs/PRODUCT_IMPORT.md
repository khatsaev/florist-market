# Массовое добавление товаров

В разделе «Товары и склад» нажмите «Импорт товаров», выберите JSON и проверьте предпросмотр. Кнопка «Добавить товары» сохраняет все новые карточки одной транзакцией. Существующие артикулы пропускаются: импорт не меняет их цены, названия, остатки и себестоимость. Повторная загрузка того же каталога не создаёт дубли.

Ошибка в любой строке или конфликт штрихкода отменяет весь импорт, включая журнал изменений. Импорт создаёт только карточки с нулевым остатком; приёмка и финансовые операции оформляются отдельно. Проверки выполняются повторно при сохранении, поэтому предпросмотр не заменяет проверку актуальной базы.

В демоверсии GitHub Pages результат сохраняется в IndexedDB текущего браузера. Загрузка не изменяет базу других посетителей или устройств. Поддержка импорта в опубликованном демо появится после отдельной публикации обновлённой сборки.

## Подготовленный каталог

Файл: [florist-market-catalog.json](../public/imports/florist-market-catalog.json). Источник: https://florist-market-catalog.khatsaev.chatgpt.site/, выгрузка 20 ноября 2026 года. В файле 57 уникальных артикулов:

| Исходная категория         | Артикулы    | Количество |
| -------------------------- | ----------- | ---------- |
| Рулонная бумага и плёнка   | PL001–PL027 | 27         |
| Бумага тишью               | BP001       | 1          |
| Жемчужные нити             | JN001–JN003 | 3          |
| Перламутровая бумага тишью | TS001–TS010 | 10         |
| Листовая однотонная бумага | LZ001–LZ006 | 6          |
| Бумажный наполнитель       | BN001–BN010 | 10         |

Названия и артикулы сохранены как в источнике. Размеры вынесены из названий без изменения единиц: например, «50×20 м»; ширину рулона и единицы нужно уточнить у владельца каталога. Названия оттенков взяты из названий товаров; точные коды цветов в источнике не указаны, поэтому графический индикатор нейтральный серый.

Все позиции отнесены к существующей категории «Упаковка». Единица учёта — «шт» (одна товарная позиция/упаковка); фасовка и продажа на метраж или вес требуют уточнения. Цены, закупочная себестоимость, штрихкоды, минимальные и фактические остатки в источнике отсутствуют. Числовые поля установлены в 0, штрихкоды оставлены пустыми. **Нулевая цена означает незаполненное значение; перед продажей укажите действительную цену.**

Фотографии и отдельные подкатегории не переносятся: текущая модель карточки не имеет таких полей. Внешние изображения и служебные ключи доступа в файл не включены.

## Формат файла

UTF-8 JSON, максимум 100 карточек и 90 КБ. Деньги — целые копейки, минимальный остаток — тысячные единицы. Пример одной позиции:

```json
{
  "version": 1,
  "products": [
    {
      "sku": "PL001",
      "barcode": "",
      "name": "Subtle pink",
      "category": "packaging",
      "size": "",
      "color": "Subtle pink",
      "colorHex": "#808080",
      "unit": "шт",
      "minStock": 0,
      "price": 0,
      "cost": 0
    }
  ]
}
```

Категории: `box`, `flask`, `packaging`, `material`. У готовой продукции единица только `шт`; у сырья также `м`, `м²`, `кг`, `л`. Поля `id`, `stock` и неизвестные поля запрещены. Повторяющиеся артикулы или непустые штрихкоды внутри одного файла отклоняются. Совпадение нового артикула со штрихкодом другого товара также отклоняется.

Одинаковый ключ операции возвращает ранее сохранённый результат; новый ключ с тем же файлом пропускает существующие артикулы. Проверки общие для серверного SQLite и браузерного sql.js.
